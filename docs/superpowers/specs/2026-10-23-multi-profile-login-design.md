# Multiple profiles and terminal login — approved design

The user confirmed detection of multiple accounts and a login button opening the official CLI flow in a Windows terminal. They provided a real example with CODEX_HOME .codex-compte1 and .codex-compte2; the product must not hard-code these names.

Selected approach: bounded automatic discovery of known profile directories, documented environment variables, plus native directory/executable selection for custom installations. Manual-only discovery would contradict the request; a full-disk search or cookie harvesting is excluded. Each profile has a distinct stable ID and its own consent. A candidate profile is not a confirmed account. Duplicates are recognized only through reliable provider identity, never by adding gauges together.

Codex: CODEX_HOME is a direct configuration directory; search for .codex and .codex-* / .codex_* in the home directory, the environment override and added directories. Claude: CLAUDE_CONFIG_DIR is isolated per process. Gemini: the installed code uses GEMINI_CLI_HOME as a home directory containing .gemini; do not treat this setting as a direct configuration directory. New profiles are created in the widget's local data and registered, without copying credentials or changing the global environment. Existing provider permissions remain limited to the default profile and are not extended to discovered profiles.

Login: Sign in, Add account, Already installed and Add profile folder buttons. Select the executable through a system dialog if it is not found. Login only through verified official commands (Codex login, Claude auth login, interactive Gemini; OpenCode auth login if confirmed). No shell text supplied by the renderer. Visible terminal, neutral working directory, no automated secret entry or acceptance of OAuth dialogs. Launching is an explicit request to log in and read the selected profile; it does not extend to other profiles. Gemini may require /auth in its terminal; no generation prompt is sent.

Refresh reruns discovery, including after installation/login; bounded monitoring of the login session reruns discovery after the terminal closes. Accounts appear separately, with independently pinnable and revocable cards. Gemini and Claude retain their previously documented quota limitations. Paths stay in main; public data contains labels and non-sensitive evidence. Sanitized persistence, serialized updates, clean shutdown, isolation/env/IPC/shell tests and native verification without real accounts. Rebuild using the same executable filename requested previously to preserve its location.
