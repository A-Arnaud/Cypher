# Multi-profils et connexion terminal — conception approuvée

L'utilisateur a confirmé la détection de plusieurs comptes et un bouton de connexion ouvrant le parcours officiel du CLI dans un terminal Windows. Il a fourni un exemple réel avec CODEX_HOME .codex-compte1 et .codex-compte2 ; le produit ne doit pas coder ces noms en dur.

Approche retenue : découverte automatique bornée des dossiers de profils connus, variables d'environnement documentées, plus sélection native de dossier/exécutable pour les installations personnalisées. Une découverte seulement manuelle contredirait la demande ; une recherche intégrale du disque ou récupération de cookies est exclue. Chaque profil a un ID stable distinct et un consentement propre. Un profil candidat n'est pas un compte confirmé. Les doublons ne sont reconnus qu'avec une identité fournisseur fiable, jamais en additionnant les jauges.

Codex : CODEX_HOME est un dossier de configuration direct ; rechercher .codex et .codex-* / .codex_* dans le home, l'override d'environnement et les dossiers ajoutés. Claude : CLAUDE_CONFIG_DIR est isolé par processus. Gemini : le code installé utilise GEMINI_CLI_HOME comme home sous lequel se trouve .gemini ; ne pas traiter ce paramètre comme un dossier de configuration direct. Les nouveaux profils sont créés dans les données locales du widget et enregistrés, sans copier des credentials ni modifier l'environnement global. Les anciennes autorisations fournisseur restent limitées au profil par défaut, pas étendues aux profils découverts.

Connexion : boutons Se connecter, Ajouter un compte, Déjà installé et Ajouter un dossier de profil. Sélection d'exécutable par dialogue système si non trouvé. Login uniquement pour commandes officielles vérifiées (Codex login, Claude auth login, Gemini interactif ; OpenCode auth login si confirmé). Aucun texte shell fourni par le renderer. Terminal visible, contexte de travail neutre, aucune saisie automatisée de secret ni acceptation des dialogues OAuth. Le lancement est une demande explicite de connexion et de lecture pour le profil sélectionné ; pas d'extension à d'autres profils. Gemini peut nécessiter /auth dans son terminal ; aucun prompt de génération n'est envoyé.

Actualiser relance la découverte, y compris après installation/connexion ; un suivi limité de la session de login relance cette découverte après fermeture du terminal. Les comptes s'affichent séparément, cartes épinglables et révocables indépendamment. Gemini et Claude gardent les limites de quotas déjà documentées. Les chemins restent dans le main, les données publiques contiennent labels et preuves non sensibles. Persistance expurgée, sérialisation des mises à jour, arrêt propre, tests isolation/env/IPC/shell et vérification native sans comptes réels. Rebuild du même nom d'exécutable demandé précédemment pour conserver son emplacement.
